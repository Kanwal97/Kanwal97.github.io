THE PROBLEM

The client needed a system that could ingest live and historical listings from a large third-party marketplace, identify each against a controlled catalogue, and score them against comparable sales.

We shipped two surfaces sharing one data floor — an internal operator console for tuning the machine, and an external end-user surface for reading its output.

HOW IT WAS BUILT

Delivered as small, reviewed pull-request slices with a pre-commit health check running formatting, tests, and level-8 static analysis on every change.

DELIVERED

  • Six production screens — decision audit, review queue, classifier versions, operator home, catalogue viewer, opportunities feed.
  • Hybrid classifier — deterministic rules run first; anything below threshold falls through to an LLM matcher that must choose from the catalogue or explicitly abstain. It cannot invent an identity that isn't there.
  • Append-only decision log — overrides never mutate; every current answer is traceable through the full attribution chain that produced it.
  • Five-input weighted signal score (0–100) with a thin-data gate — records below the comparable-sales threshold stay un-scored, because a low score would read as signal where none exists.
  • Compliance webhook shipped in Phase I — SHA-256 challenge and RSA signature verification against the marketplace's rotating public keys, plus an idempotent scrub across every table that could hold a user identifier.
